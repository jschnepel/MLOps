# Development scenario cards — not executed tests

These 32 cards define concrete adversarial, multi-turn, and recovery scenarios for a future harness. Each maps to acceptance requirements and a final-state oracle. `max_matching_incidents` is an upper bound, not a claim that an incident exists. A harness must model test-specific approvals/clock/faults and check the stated outcome; do not treat the natural-language oracle as an automated grader by itself.

Expand/review to the planned 80 development cases. A separate reviewer controls 40 final held-out cases; no held-out set or benchmark score is included. Do not treat generated variants already read by the tuning agent as unseen. Reset application and destination data per independent trial.
